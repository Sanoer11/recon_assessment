  Summary

  Schemas
  - ledger.csv: txn_id, created_at (ISO, +05:30), amount, currency, fee, 
    merchant_id, type (sale|refund), status — clean, no noise.
  - bank_statement.csv: settle_date, amount, reference, description, 
    running_balance — messy (mixed date formats, Indian digit grouping,
    whitespace noise). Row 1 is always BAL B/F opening balance (bucket
    non_transaction); last row is the Oct-31 CHRG account-maintenance line
    (bucket bank_only, −590.00).

  Buckets (from ground_truth.json): matched, timing_difference, 
  rounding_variance, duplicate, unmatched_refund, bank_only, non_transaction.
  I'll add non-ground-truth buckets (amount_mismatch, generic unmatched) for
  production robustness/mutation tests, since the engine must never silently
  force something into a wrong bucket.

  Reference formats (money/ids always separated from letters since hex digits
  never include t/x/n, so no ambiguity):
  - One-to-one sale: NEFT/<UTR>/PAYGW SETTL txn_<12hex> | PAYGW/<10HEX>
    (prefix-stripped, truncated, upper) | <UTR>-STL-TXN<12HEX>-<merchant>
  - Batch: NEFT/<UTR>/PAYGW BATCH B-<merchant>-<YYYYMMDD> | PAYGW SETTL 
    B<merchant><YYYYMMDD> (dashes stripped)
  - Refund: PAYGW RFND txn_<12hex> | NEFT/<UTR>/RFND/<10HEX>
  - UTR: (UTIB|HDFC)N<yy><day-of-year:03d><6digits>

  Matching plan
  - S1 (ref→txn): regex anchored on txn_, PAYGW/, STL-TXN, RFND/ markers to pull
    a 10–12 char hex run (case-insensitive); resolve via full id or unique
    10-hex prefix.
  - S2 (ref→batch): regex B-?(M\d{3})-?(\d{8}) reconstructs B-<merchant>-<date>;
    group ledger sales by (merchant, capture_date) for the 8 batch merchants;
    compare sum(net) to bank amount.
  - S3 (fallback): amount + merchant + settle-date window (capture+1..2 business
    days, small buffer) for whatever's left; flagged low-confidence.
  - Classification: batch diff ≠ 0 → recompute round(gross × 2.36%) once; if it
    exactly explains the diff, whole batch → rounding_variance (never a single
    line); otherwise → amount_mismatch (real exception, exercised by mutation
    tests). Unmatched sale with no settlement → check same-merchant/same-amount
    sibling within ~10 min that is matched → duplicate; else compute
    minimum-possible settle date from the generator's RBI business-day calendar
    (if even lag=1 pushes past Oct 31, or lag must have been 2 given it's
    missing) → timing_difference. Unmatched/matched refund with no
    same-merchant/same-abs-amount prior sale anywhere in the ledger →
    unmatched_refund (even though it settled at the bank — net bridge effect 0,
    still a control exception).

  Proceeding now: normalize → engine → tests → CLI → site → README, committing
  after each step, without touching ground_truth.json from engine code.
